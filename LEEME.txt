Didppi
======

Recorrido para armar el motor de inferencia de un pedido a domicilio.
La interfaz está en React. El motor está en Python. En Vercel se publica
como un solo proyecto: la raíz del proyecto es esta carpeta.

Los estudiantes abren la ruta, encajan los siete métodos y pueden cambiar
el pedido. Si una pieza no se entiende, el botón «Consultar el concepto»
explica la cuenta con otros números y afloja la actividad.

Desde la portada hay un segundo recorrido: el subsistema de consultas.
El mismo pedido llega sin datos y el motor los pregunta. Tiene tres partes:
una consulta en vivo (el estudiante responde como el cliente, incluso
«No sé»), las estructuras de Python que la guardan y siete piezas de código.

El tercer recorrido es el subsistema de explicaciones. La misma consulta
anota cada paso en una traza; con ella responde WHY («¿por qué me
preguntas esto?») y HOW («¿cómo llegaste a esa conclusión?»). Tiene una
consulta en vivo, las estructuras de la traza, siete piezas (algoritmos
A a G) y el código completo de motor/explicaciones.py para repasar.

Qué editar
----------

motor/politicas.py              las reglas del restaurante
motor/casos.py                  los pedidos de ejemplo y CASOS_CONSULTA
motor/consultas.py              el subsistema de consultas (la clase Consulta)
src/consultas/contenido.js      las piezas y las estructuras del segundo recorrido
src/consultas/comentarios.js    el botón ? de esas piezas
motor/explicaciones.py          Evento, Traza y ConsultaExplicable (WHY y HOW)
src/explicaciones/contenido.js  las piezas y las estructuras del tercer recorrido
src/explicaciones/comentarios.js el botón ? de esas piezas

Rutas del subsistema de consultas:

    GET  /api/consultas/guia    casos, recorridos y estructuras
    POST /api/consultas/paso    {"respuestas": {"pidio_cancelar": "no", "llueve": null}}

null es «no sé». La respuesta trae el estado de cada regla, los puntajes
y la siguiente pregunta, o el fin de la consulta.

Rutas del subsistema de explicaciones:

    GET  /api/explicaciones/guia    casos, estructuras y código
    POST /api/explicaciones/paso    {"pasos": [["pidio_cancelar", "por qué"], ["pidio_cancelar", "no"]]}

Los pasos van en el orden en que el motor pregunta. La respuesta trae la
traza, el diálogo con cada WHY y, al final, el HOW como frase y como árbol.

Correr en local
---------------

Terminal 1, desde esta carpeta:

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    uvicorn app:app --reload --port 8000

Terminal 2:

    npm install
    npm run dev

Abrir http://localhost:5173

La comanda llama a http://127.0.0.1:8000/api. Vite reenvía /api hacia ahí.

Sin interfaz, los mismos casos:

    python3 -m motor ana
    python3 -m motor todos

Pruebas del motor:

    python3 -m unittest tests.test_despacho tests.test_consultas tests.test_explicaciones

Publicar en Vercel
------------------

1. Importa el repositorio.
2. En Root Directory elige ensamble. No uses la carpeta de todo el curso.
3. El Framework Preset tiene que ser FastAPI. Vercel instala Python por
   requirements.txt y corre el build de npm.
4. La interfaz queda en el mismo dominio que /api/salud.

El archivo de entrada del backend es app.py. La interfaz compilada queda
en dist/, y Vercel la sirve desde ahí.
